# 🐎 Horse Racing Management System (경마 관리 시스템)

> **4주차 오픈 미션: 대규모 사용자 관리 및 경주 시뮬레이션 구현**

이 프로젝트는 선수(Player)와 관객(Audience)의 상호작용, 그리고 다양한 승식(Betting Type)에 따른 복잡한 배당률 계산 로직을 다루는 **JavaScript 기반의 콘솔 경마 시뮬레이션**입니다. 단순한 경주를 넘어, 데이터의 정합성 검증과 객체 지향적인 설계를 목표로 하였습니다.

---

## 📖 프로젝트 소개 (Mission Description)

**'경주 시스템과 다수의 사용자를 관리하는 대규모 시스템 구현'**

본 시스템은 경마의 전 과정을 시뮬레이션합니다. 선수의 등록부터 관객의 베팅, 실제 경주 시뮬레이션, 그리고 배당금 정산까지의 흐름을 유기적으로 연결하여 실제 경마장의 프로세스를 소프트웨어로 구현했습니다.

## 🎲 게임 규칙: 승식 (Betting Rules)

이 게임은 실제 경마 시스템의 승식 규칙을 따릅니다. 관객은 전략에 따라 4가지 방식 중 하나를 선택하여 베팅할 수 있습니다.

|     승식 (Type)     | 설명 (Description)                              | 선택 말 수 |
| :-----------------: | :---------------------------------------------- | :--------: |
|   **단승 (Win)**    | 1등으로 들어올 말 **1마리**를 적중              |     1      |
|  **연승 (Place)**   | 3등 안에 들어올 말 **1마리**를 적중             |     1      |
| **복승 (Quinella)** | 1등과 2등 말 **2마리**를 **순서 상관없이** 적중 |     2      |
|  **쌍승 (Exacta)**  | 1등과 2등 말 **2마리**를 **순서대로** 적중      |     2      |

## 📋 기능 명세 (Feature Specifications)

### 1. 선수 및 경주마 등록 (Registration)

경기에 참가할 선수와 말의 정보를 데이터베이스에 등록합니다.

- **입력:** `선수이름,말이름` 쌍으로 입력.
- **제약 조건:** 오직 문자만 허용되며, 중복된 이름은 등록할 수 없습니다.
- **종료:** `0` 입력 시 등록 마감.

### 2. 출석 체크 (Attendance Check)

등록된 명단을 바탕으로 실제 경기장에 도착한 인원을 확정합니다.

- **검증:** 입력된 {선수, 말} 조합이 등록 명단과 일치해야 합니다.
- **실격:** 출석하지 않은 선수는 경기 라인업에서 제외됩니다.
- **자동 진행:** 전원 출석 시 별도 종료 명령 없이 다음 단계로 넘어갑니다.

### 3. 관객 입장 및 베팅 (Spectators & Betting)

#### 🎟️ 입장 관리

- 기본 입장료는 **2,000원**입니다.
- 초과 금액 지불 시 잔돈을 계산하여 반환합니다.

#### 📝 OMR 베팅 시스템

- **베팅 단위:** 1,000원 단위로만 가능합니다.
- **유효성 검사:** 승식에 맞지 않는 말의 수(예: 단승에 2마리)를 입력하면 재입력을 요구합니다.
- **마감:** `STOP` 입력 시 베팅을 종료하고 경기를 시작합니다.

### 4. 경기 진행 (Race Simulation)

경주마들이 결승선을 향해 달리는 시뮬레이션 단계입니다.

- **승리 조건:** 총 **5칸**을 먼저 통과한 순서대로 순위가 결정됩니다.
- **이동 로직:**
  - 매 턴 $1 \sim 45$ 사이의 난수 생성.
  - 난수가 **$25$ 초과**일 경우 1칸 전진.
  - 그 외의 경우 제자리 유지.

### 5. 정산 및 결과 리포트 (Settlement)

#### 💰 배당률 계산 (Dividend Calculation)

배당률은 각 승식별 풀(Pool)에 따라 독립적으로 계산됩니다.

$$
\text{배당률} = \frac{\text{총 베팅 풀 (Total Pool)}}{\text{승리 풀 (Winning Pool)}}
$$

#### 📊 최종 리포트

경기 종료 후 모든 관객의 결과를 출력합니다:
`[관객 이름]`, `[승식]`, `[베팅금]`, `[선택한 말]`, `[최종 수익]`

- 예측 실패 시 베팅금은 전액 몰수됩니다.

    F --> G[🏁 경기 진행 (Random Simulation)]

## 🛡️ 예외 처리 및 유효성 검사 (Exception Handling & Validation)

안정적인 시스템 운영을 위해 각 단계별로 엄격한 입력 검증 규칙(Strict Validation Rules)을 적용했습니다.

### 1. 선수 및 경주마 등록 (Registration Phase)

입력된 데이터의 무결성을 보장하고 게임 성립 조건을 확인합니다.

- [x] **형식 준수:** 선수와 말의 이름은 반드시 쉼표(`,`)로 구분되어야 합니다.
- [x] **문자 제한:** 이름에 특수문자(`@`, `#` 등)나 공백이 포함될 수 없습니다.
- [x] **게임 성립 조건:** 출석한 선수가 **0명 또는 1명**일 경우, 경쟁이 성립되지 않으므로 프로그램을 즉시 종료합니다.

> **🚫 Bad Cases (입력 불가 예시)**
>
> ```diff
> - minuk@chichi       (특수문자 포함 불가)
> - min uk,chi chi     (공백 포함 불가)
> - minuk/chichi       (구분자 오류)
> ```

### 2. 관객 및 입장료 관리 (Spectator Management)

관객의 정보와 금전적 입력에 대한 숫자 및 형식 검증을 수행합니다.

- [x] **숫자 검증:** 입장료나 소지금은 오직 **숫자(Integer)** 형태여야 합니다.
- [x] **금액 제약:**
  - 입장료는 최소 **2,000원** 이상이어야 합니다.
  - 베팅금 및 입장료는 **1,000원 단위**로만 입력 가능합니다.
- [x] **형식 준수:** 숫자 입력 시 쉼표(`,`)나 공백이 포함되어서는 안 됩니다.

> **🚫 Bad Cases (입력 불가 예시)**
>
> ```diff
> - 백만원             (한글 입력 불가)
> - 1000 won           (단위 표기 불가, 숫자만 허용)
> - 10,000             (쉼표 포함 불가)
> - 2 000              (공백 포함 불가)
> - 300                (최소 금액 미달)
> ```

### 3. OMR 베팅 검증 (Betting Slip Validation)

OMR 카드의 데이터 파싱 과정에서 발생할 수 있는 오류를 차단합니다.

- [x] **구분자 확인:** 모든 데이터는 슬래시(`/`)를 통해 명확히 구분되어야 합니다.
- [x] **승식 명칭:** 시스템에 정의된 정확한 승식 명칭(단승, 연승, 복승, 쌍승)만 허용합니다.
- [x] **말 선택 수 검증:** 선택한 승식에 따라 입력해야 하는 말의 개수가 일치해야 합니다.

|   승식 (Type)   | 필요 말 개수 (Horse Count) | 비고               |
| :-------------: | :------------------------: | :----------------- |
| **단승 / 연승** |           1마리            | 2마리 입력 시 에러 |
| **복승 / 쌍승** |           2마리            | 1마리 입력 시 에러 |

> **🚫 Bad Cases (입력 불가 예시)**
>
> ```diff
> - " 복승식 "         (공백 또는 잘못된 명칭)
> - @복 승             (특수문자 포함)
> - 단승/복승,chichi   (잘못된 구분자 혼용)
> - 단승/1000/말1/말2  (단승에 말이 2마리 입력됨 -> Error)
> ```
